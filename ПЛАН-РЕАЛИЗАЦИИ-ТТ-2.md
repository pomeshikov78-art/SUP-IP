# План дальнейшей реализации требований ТТ-2

**Дата:** 2026-11-25 · **Текущая версия:** 1.16.0 · **Интегральная полнота:** ~55–65 %
**Связанный документ:** «ОЦЕНКА-РЕАЛИЗАЦИИ-ТТ-2.md» (состав пробелов и доказательства).

---

## 1. Принципы и порядок работ

1. **Строгое соответствие ТТ-2.** Каждая операция реализуется по функциональной и экранной
   спецификации соответствующего модуля; отклонения фиксируются в README §9 с обоснованием
   (как уже сделано для привязки поручений к Task M02 и backward-compatible миграций).
2. **Одна операция — один релиз.** После каждой операции: новая версия `X.Y.Z`, копия README
   в `versions/README-vX.Y.Z.md`, запись в CHANGELOG, пересборка руководств и архива, пуш в
   `master`/`main`, тег, автосборка CI и публикация Release. Несколько операций в одном релизе
   не накапливаются.
3. **Испытания прежде публикации.** Каждый релиз сопровождается профильным набором серверных
   проверок и блоком E2E; полный регресс должен проходить без FAIL до пуша тега.
4. **Схема БД — backward-compatible.** Новые поля и таблицы добавляются миграциями со сходимостью
   при запуске; базовая схема включает всё из миграций; резервная копия и восстановление копий
   прежних версий сохраняются.
5. **Автономность.** Без CDN/интернета в клиенте; шрифты и ресурсы в поставке; PostgreSQL обязателен.
6. **Документация.** Руководства пользователя и администратора обновляются под каждый релиз.

**Приоритет очередей:** сначала завершение M16 (активная область, наибольшая готовность),
затем крупнейшие относительные пробелы (M17, M11), затем углубление M14/M15/M05/M07/M00/M13
и остальных модулей, затем сквозные нефункциональные требования и полная приёмка.

## 7. Зависимости и риски

| Риск / зависимость | Влияние | Мера |
|---|---|---|
| Матрица прав §2.14 (8 ролей) vs текущие 5 ролей | ломает совместимость настроек | маппинг ролей + миграция прав в v1.17.0 |
| Статусы поручений поверх Task M02 | расхождение enum §16.4 | производный статус + справочник (очередь E) |
| M17 зависит от метрик M11 | порядок работ | сначала движок M11 (очередь B), либо параллельно с фиксацией контракта |
| Рост схемы БД | миграции и копии | backward-compatible, сходимость, тесты `schema_test` |
| Объём экранных спецификаций | трудоёмкость | декомпозиция по экранам, один релиз — группа экранов |
| Стеснённая среда CI/E2E (ОЗУ) | флейки E2E | ожидание результата вместо пауз, лимиты памяти Chrome (уже применено) |

самостоятельная операция с версией, README в `versions/`, испытаниями, CI и Release.
